Theory Sprint v2.2 수정내역
수정일시: 2026-09-25 21:23 KST

[시험평가관리]
1. 전체 흐름 재구성
- 연구개발과 구매를 하나의 직선 흐름으로 섞지 않고 두 갈래로 분리.
- 연구개발: 운용성확인 → 체계개발 → TEMP → DT/OT 세부계획 → DT/OT
- 구매: 시험평가 대상장비 선정 → 구매시험평가계획 → 시험평가 → 기종결정

2. 운용성확인 명확화
- 시험평가관리의 운용성확인은 탐색개발 기간 중 잠재적 운용효과·운용적합성에 관한 의사결정 자료를 조기에 확보하는 절차로 설명.
- 상호운용성 과목의 운용성확인은 상호운용성 요구사항의 반영·구현 가능성을 확인하는 관련 평가이며, 합참·국방부의 상호운용성 평가결과가 전체 운용성확인 결과와 함께 검토됨을 명시.
- 함정사업은 운용성확인을 함정 기본설계시험평가로 대체 가능하다는 현행 표현 유지.

3. TEMP 위치 교정
- TEMP를 시험단계로 보이지 않게 수정.
- TEMP = 체계개발 전체 시험평가의 상위 시험평가기본계획서.
- TEMP → DT계획·OT계획 → DT·OT 수행의 위계를 명시.

4. 계획문서 구조 개선
- '운용성·TEMP·DT·OT·구매 다섯 축' 삭제.
- 탐색개발: 운용성확인계획서
- 체계개발 상위: TEMP
- 체계개발 세부: 개발시험평가계획서 / 운용시험평가계획서
- 구매사업: 구매시험평가계획

5. 구매시험 용어 수정
- '후보장비' 중심 표현을 '시험평가 대상장비'로 변경.
- '통합체계지원요소'를 현행 '전력화지원요소'로 수정.
- 구매시험평가계획의 대상장비·수량·기간·장소·방법·항목·기준 구조를 명확화.

6. KPP/KPI 정리
- TEMP 현행 서식 문구인 '주요효과도(KPP 등) 및 적합성 측정기준'을 기준으로 재작성.
- KPP = Key Performance Parameter.
- KPI = Key Performance Indicator로서 일반 성과관리 지표이며 KPP와 구분.
- ROC는 군의 작전운용 요구, TEMP는 이를 시험 가능한 항목·기준·주요효과도와 연결하는 구조로 설명.

7. 판정용어 비교 카드 신설(기존 오답 카드 대체)
- 상호운용성 운용성확인: 적합 / 주요 결함사항 / 도출된 문제점 / 개선 및 발전시킬 사항
- 전체 운용성확인: 항목별 결과 + 결함·문제·개선·발전사항 + 다음 단계 전환 의견
- DT: 기준 충족 / 기준 미달
- 연구개발 OT: 전투용 적합 / 전투용 조건부 적합 / 전투용 부적합
- 구매시험: 전투용 적합 / 전투용 부적합

- '오답1~4' 형식 대신 무엇이 어떻게 다른지를 직접 비교하는 카드로 변경.
